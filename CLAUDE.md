## Conventions

- **Server data is in the query cache, never in a context's state.** Add a query to `hooks/queries.ts` and a key to `queryKeys`; write answers with `queryClient.setQueryData`. The contexts (`useOnboarding().onboardingData`, `useDiet().dietData`, `useProjection().projectionData`) are read-only views plus patch functions. Everything persisted is wiped by `signOut()` (`clearQueryCache`). The persister writes asynchronously and at most once a second: `clearQueryCache` sets a `wiping` flag so a copy taken mid-wipe is empty (`signOutPersist.test.ts`), and tests wait for the write itself (spy on `AsyncStorage.setItem`), never a fixed window (`queryCache.test.tsx`).
- **Routing is the session store's job.** No screen picks a route from saved answers. After sign-in call `sessionStore.setSignedIn(result)` (or `setReady()` when onboarding ends) then `router.replace('/')`. New app screens go inside the `Stack.Protected` group in `app/_layout.tsx` (a test fails otherwise). A turned-away user lands on `app/onboarding/index.tsx`, which redirects to `/`.
- **401 is handled in the api client**, not in screens: do not call `signOut()` from a screen because a request failed with 401. 403 means wrong role. `normalizeApiError(...).kind === 'cancelled'` is not an error to show.
- **Failure is not "no data".** A request that fails shows `ErrorState` with a retry (or keeps the data already on screen). Never fall back to `[]`, `null` or "start the wizard". `onboardingService.get*` rejects on error and resolves `null` only for "nothing saved".
- **One `signOut()`** (`services/session.ts`) for logout, account deletion and an invalid session. It never throws. A store that holds per-user data registers a reset with `registerSessionResetter` in a `useEffect`. A loader that writes into a store captures `getSessionEpoch()` first and drops its result if `isSessionCurrent(epoch)` is false. `__tests__/architecture.test.ts` fails if a screen calls Firebase sign-out itself.
- **Design tokens, not palettes.** Read colours, spacing and type from `useTheme().tokens` (`tokens.color.text`, `.surface`, `.accent`, `.onAccent` ...) and build screens from `src/ui`. No `isDarkMode ? a : b` and no `Colors.gray[n]` in a screen you touch (`__tests__/architecture.test.ts` lists the migrated screens). Text on the coral accent is `onAccent` (dark navy), never white: white on coral is 2.8:1. Every text/background pair in `TEXT_PAIRS` is tested for 4.5:1 in both themes (`tokens.test.ts`); add a pair there when you add a token that carries text.
- **Primitives.** Wizard steps are `<WizardStep>` (back + progress on top, heading right under it, Continue pinned at the bottom: never centre the body vertically). Messages and confirmations are `Dialog` (or `useToast()` for non-blocking), pickers are `Sheet` and `WheelPicker` (one virtualised implementation), loading is `Skeleton`, no data is `EmptyState`, failure is `ErrorState`. Do not hand-roll a `Modal` for an alert (a test fails on `<Modal` and `Alert.alert` outside `src/ui`; the camera uses `FullScreen`). Images are `AppImage` (expo-image, cached, placeholder).
- **Wizards are config.** A Diet or Projection question is an entry in `src/wizard/flows.ts` (title key, options, field) and its route file is `return renderStep('diet-meals')`. Saved answers are preselected, Back goes to the previous question (or to the profile when editing), Continue saves with the same field names and shapes as before. Do not write another screen per question. The onboarding screens use `WizardStep` and preselect from `onboardingData`.
- **Scan result.** `ScanResult` reads fields through `itemsFromScan` (the api shape and the older flat names). `needsConfirmation` and `alternatives` are **per item** (CONTRACTS 3.7); when no prediction carries them (older api) the scan-level ones go to the first item. An item marked `needsConfirmation` shows "Not sure", an orange border and its alternatives; low confidence alone marks an item only on older scans (`confirmKnown` false). An alternative with `classId` and `nutrition` (`canApply`) is a one-tap switch (`alternativeClassId`, shown at once via `withAlternative`, chip "Name · N cal"); one without is a rename (`foodName`) with a note that the numbers stay. Names are shown through `foodLabel` (capital first letter; catalogue names are lower case). Corrections go to `PATCH /food-scans/{id}` through `saveScanEdits` in `src/scan/saveEdits.ts`: body `{items:[{classId, grams?, foodName?, alternativeClassId?}], confirmed?}` with **only the changed items** (`editItems` returns `[]` for none, null when a change cannot be expressed); grams are whole numbers 1 to 5000, from the alternative's weight when one was picked; the edit shows at once and is rolled back with a toast if the save fails; 409 refetches the scan and retries once, then says so, except a 409 refusing an alternative (`alternativeUnavailable`: not retried, a dialog offers "Rename only" or a rescan); 404 (older server) keeps the edit on screen only and shows a note; 400 and offline have their own messages (400 after a pick says the choice is no longer offered); 401 is the api client's job. A saved scan replaces the one on screen and in the Home and History caches (`applyScanToCaches`). "Looks right" sends `confirmed: true`. `ScanProgress` shows upload, analyze and finish as real steps with the time so far and Cancel.
- **Brand.** Logos come from `BrandLogo` (symbol or horizontal lockup, light or dark version by theme) and the files in `assets/images/brand` (copied from the landing repo `brand/`, concept Summit); the app icon, adaptive layers and splash are wired in `app.config.ts` and tested in `brandAssets.test.tsx`. Do not recolour or redraw the mark; ask for a new kit instead. Only a device build shows the real home-screen icon, the adaptive-icon masks and the splash.
- **Scan result as a sheet.** Home and History open `/scan-result?scanId=` (`app/scan-result.tsx`, a root route re-exporting `app/diet/diet-statistics.tsx`), presented by the root Stack as a `transparentModal` sliding up. A root `Stack.Screen` must never name a route inside a folder with its own `_layout` (expo-router ignores it as "extraneous", options included; the architecture test checks it): that is how `diet/diet-statistics` lost its modal presentation. The Diet tab still renders the screen inline after a new scan.
- **No navigator header anywhere (owner's choice, 2026-11-14).** Every navigator has `headerShown: false` and no `header` option; no screen turns one on, uses `headerRight` or `navigation.setOptions` (architecture test; `navigation.test.tsx` checks `HeaderShownContext` is false in the tabs, pushed screens and the Profile and Diet stacks). A pushed screen starts its scrolling content with `PageHeader` (`src/ui/PageHeader.tsx`): a round 40 pt `BackButton` (44 pt target) with an optional action on the right (History's filter), then a large `title`; it scrolls with the page. Its back uses `useRouter()` (`router.canGoBack()/back()`, the same action as Android back), not the nearest navigator: `navigation.canGoBack()` is false on the first screen of a nested stack (every Profile screen). A screen shown inside a tab that is not a route (the barcode result, Diet step 6) passes `back onBack`. Home's first row is the logo and the Pro plan chip (opens `ProPlanModal`), scrolling with the page. Chat keeps its pinned row (back + title) because its messages are the scrolling part, with the same `BackButton`. The scan-result sheet keeps its own handle and close button.
- **Top inset: one small gap, nothing stacked.** `Screen` adds the status-bar inset plus `TOP_GAP` (4, exported from `src/ui/Screen.tsx`) itself, as a fixed spacer (or as the pinned header's top padding), so content never scrolls under the status bar; not under a navigator header (`HeaderShownContext`; none is shown now) or with `noTopInset` (no screen uses it now). Nothing else adds top padding above a screen's first row: `PageHeader`, Home's logo row, the Profile, Workouts and Diet content, Login's buttons and a wizard's progress row all start right at the gap (`screenInset.test.tsx`). The first rows are 44 pt touch targets, so their visible part may sit a few points lower. Where the host draws the app below an opaque status bar (insets.top 0), that bar, painted in the theme colour by `SystemBars`, is the only other space; the trace's `layout` line tells which case a phone is in. Old screens without `Screen` (Workouts, FAQ, Help, My data, projection statistics) are wrapped in `<Screen padded={false}>`; `ScanResult` inline (Diet tab) adds its own spacer, the sheet does not. Tabs use `backBehavior="history"` (Android back returns to the previous tab; Home with nothing behind leaves the app). The Diet tab's steps are not routes: `dietBackStep` (services/onboardingResume.ts) maps Android back (question to previous question, result 5/6 to the scan 4; the first question and the scan itself leave the tab). Sign-in, sign-out, account deletion and the end of onboarding use `router.replace('/')` on purpose. `__tests__/navigation.test.tsx` drives the real tab, Profile, Diet, Projection and onboarding layouts with `renderRouter` from `expo-router/testing-library` (works with Testing Library 13; its `screen.getPathname` needs a type cast).
- **Session and navigator (found with the device trace).** After the first launch the session never goes back to `'loading'`: `runLaunchCheck` shows the launch screen only for the first check (or "Try again"), a later check runs in the background and a failed one leaves the session as it is; `RootContent` checks only while the status is `'loading'` (a Fast Refresh or a React Activity reconnect re-runs effects) and, once the navigator is shown, keeps it mounted. Swapping the navigator for the launch screen threw the history away ("ROUTE_NAMES_CHANGED was not handled" in the log) and Android back then closed the app. `__tests__/launchRecheck.test.tsx` covers it.
- **Dev-only navigation trace.** `src/dev/NavigationTrace.tsx` logs `[alphafit-trace]` lines to Metro (route + stack depth per navigator, every hardware back that reaches JS, session status changes, every language and light/dark change, and a `layout` line at start and on each change: safe-area insets, `StatusBar.currentHeight`, window and screen sizes, pixel ratio; window height equal to screen height with insets.top > 0 means the app is drawn under the status bar, a shorter window with insets.top 0 means below an opaque bar). Its `session ... | root instance N` line is logged when it mounts: a new N without a JS reload means the app root was mounted again (state and history lost); the same N means only effects re-ran (Fast Refresh). On 2026-11-14 the phone showed six language changes and several theme toggles with no new instance and no route line. Loaded only through `__DEV__ ? require(...) : null` in `app/_layout.tsx` (architecture test); `scripts/check-bundle.js` fails if the tag is in an export. Only it and `services/apiError.ts` may use `console`.
- **System bars and top bars.** `SystemBars` in `app/_layout.tsx` sets the window root background to the theme (`expo-system-ui`; where the host does not draw edge-to-edge, e.g. Expo Go on some phones, that is what shows behind the system bars) and the status-bar and navigation-bar icon style (`expo-status-bar`, `expo-navigation-bar`). RN 0.88 / SDK 58 have no API to colour or make the bars translucent. The compact top bars of WP-MOB-12 (`src/ui/TopBar.tsx`) are gone with every other navigator header.
- **Login and Register** are one centred flow (`Screen centered`: the body is centred in the scroll frame, which the keyboard does not resize, so it does not jump). Register has no top bar; its "Sign in" and Login's "Sign up" use `useSwitchTo` (`src/wizard/useSwitchTo.ts`): go back when the other screen is right below, else open it, so they never pile up.
- **Centre tab-bar button.** `src/scan/ScanTabButton` (coral, 56 pt, label "Scan food", haptic) sits in the `scan` slot of `app/(tabs)/_layout.tsx`; `app/(tabs)/scan.tsx` is only the slot (a link to `/scan` is sent on). `useOpenFoodScan` (`src/scan/openScan.ts`) sets the Diet step from the cached diet answers (`scanEntryStep`: the first unanswered question, else 4 = the scan; unknown answers leave it to the Diet tab) and navigates to `/(tabs)/diet`. The hidden Projections tab has its own plain icon.
- **Home, History, Chat (MOB-6).** Home makes no chat-model call on mount or refresh; its week strip (`src/scan/week.ts`) marks the last seven days that have completed scans among the 50 loaded. History loads one page at a time (an in-flight guard), tells a failed first page, a failed refresh (banner) and a failed next page apart, and its filters only look at the loaded pages (the api has no status filter): it says so and auto-loads at most four more pages. Chat shows the newest 30 messages and pages older ones in (the api returns the whole history), sends only the latest 20 as context, and offers a retry when the history could not be loaded. Profile shows a placeholder, not the empty "Add Photo" slot, while the picture is looked up.
- **Images before upload** are shrunk by `services/imagePrep.ts` (longest side 1280 px, JPEG 0.8); it falls back to the original on any failure.
- **Feel.** Press feedback comes from `PressableScale`; entrances use `enter(index, reduce)`; haptics go through `haptic.select/confirm/error/shutter`. Every animation checks `useReduceMotion()`.
- **Theme switch with a circular reveal (WP-MOB-13).** `src/ui/ThemeTransition.tsx` (`ThemeTransitionProvider` in `AppProviders`, under `ThemeProvider`): a user's change goes through `useThemeTransition()` (`toggleTheme(origin)`, `setThemeFrom(pref, origin)`, origin = `originOf(pressEvent)`): Skia `makeImageFromView` captures the app, the theme switches underneath, and the old picture is drawn on top with a `blendMode="clear"` circle growing from the press point to the farthest corner (`REVEAL_MS` 450, ease-out, Reanimated on the UI thread); a timer removes the overlay. Reduced motion, no origin, or a change that keeps light/dark: instant. A second tap during the reveal is ignored; a failed capture switches at once (logged). The phone's own appearance change never goes through it. The change is applied one frame after the snapshot is shown (`requestAnimationFrame`), so the old picture is drawn before anything under it moves. `@shopify/react-native-skia` 2.14.0 is in Expo Go 58; Jest uses a stand-in from `jest.setup.js`.
- **Language switch: no animation (owner's choice), just smooth.** `LanguageSelector` marks the tapped language at once, closes, and calls `onSelect` from `Sheet.onClosed` (the sheet animates out over `SHEET_EXIT_MS`, 180, before its modal goes), so nothing re-renders under a sheet still on screen; the screen then calls `setLanguage` and every text changes in one render. Profile > Language marks the choice, switches at once, and goes back after 250 ms. A crossfade over a snapshot was tried and removed on the owner's request; do not animate the language. `__tests__/languageSwitch.test.tsx` (real root layout and navigator for Login, real Profile stack for Settings and Language) covers the order, the texts, the typed e-mail surviving (no remount), the trace showing no new root, and a server push that never answers.
- **Theme preference** is `system | light | dark` (`useTheme().preference`, `setTheme`). `system` is kept on the phone only; the server is told `light` or `dark` only.
- **Providers once.** Only `context/AppProviders.tsx` renders the four providers and only `app/_layout.tsx` renders it. Nested layouts must not mount providers.
- **Language and theme.** Read from storage at start (no request), sent to the server only on a user change. Use `setLanguage()` (never `i18n.changeLanguage`) and `useTheme().setTheme/toggleTheme`. `setLanguage` switches synchronously (bundled translations), then saves on the phone and tells the account side by side; nothing waits for them, a failure is logged and the language stays, and its promise never rejects. `signOut` resets the theme to the phone's and keeps the language.
- **i18n.** Every visible string is `t('key')`, no `t('key', 'English default')`, no `t(key) || 'x'` (`t` returns the key, so the fallback never runs). en, fr and es keep identical keys and `{{placeholders}}`; add to all three with real translations. Dynamic keys must have a fixed prefix (`` t(`faq.items.${id}.question`) ``); tables of keys use string values (`titleKey: 'home.title'`) so the audit sees them.
- **Logging.** `logError(context, error)` only; it prints kind, status and code, never headers, bodies or tokens (axios errors carry the `Authorization` header). No `console` anywhere else (a test enforces it). No `console` monkey-patching.
- **Api date-times** are UTC without a zone (CONTRACTS section 1): read them with `parseApiDate` / `isSameLocalDay` from `services/apiTime.ts`, never `new Date(value)`. Jest runs in Europe/Paris (`jest.globalSetup.js`) so a local-time read fails on any machine; `apiTime.test.ts` also runs the helpers in America/New_York in a child process (a Jest worker cannot change its own `TZ`).
- **Expo Go (SDK 58).** Every native module the app imports must be in Expo Go SDK 58 or be loaded through `services/nativeModules.ts`. Checked 2026-11-14 against expo/expo `sdk-58` (`apps/expo-go/package.json`, the Podfile and settings.gradle exclude lists): all Expo modules used here, reanimated 4.7.1, worklets 0.13.0, gesture-handler 3.3, screens 4.30, safe-area-context 5.11, netinfo 12.0.1, async-storage 2.2.0 and **keyboard-controller 1.22.7 are in Expo Go** (the app pins the same versions); `@react-native-google-signin/google-signin` is **not** (it throws on import via `TurboModuleRegistry.getEnforcing`). `getGoogleSignin()` requires it lazily, never in Expo Go (`isExpoGo()` = Expo's `isRunningInExpoGo()`, the `ExpoGo` native module; Expo Go 58 does **not** report `executionEnvironment` "storeClient") and only when `TurboModuleRegistry.get('RNGoogleSignin')` finds the native module; a missing module returns null silently (no `logError`, no LogBox), a module that is there but fails is logged. Login hides the Google button then. Jest runs as a development build: `jest.setup.js` mocks `isRunningInExpoGo` to false (jest-expo's own mocks would say Expo Go) and makes the registry report `RNGoogleSignin`. The architecture test forbids importing the package anywhere else; `expoGo.test.tsx` (real `expo`, executionEnvironment "bare", package throwing) and `nativeModules.test.ts` cover Expo Go, a binary without the module, and a failing load. A new native dependency: check it is in Expo Go SDK 58 first, or load it the same way. JS of reanimated may be a patch ahead of Expo Go's native (it compares major.minor); worklets must match exactly.
- **Uploads** go through `services/uploadPart.ts` (`imageFormData`): `{uri,name,type}` on a phone, a Blob with a file name on web.
- **Dates.** `dateOfBirth.month` is 1 to 12 (the api reads `LocalDate.of`). Builds before 2026-11 stored 0 to 11; `normalizeStoredMonth` reads a 0 as January.
- **Accessibility.** `accessibilityRole` on every touchable (a test fails otherwise) and a label on icon-only ones; targets 44 pt; text scales to 1.5x (`Text` caps it). Wheels are one `adjustable` control with increment and decrement.
- **Tests.** New behaviour gets a test that fails without it. Mock native modules and Firebase (`jest.setup.js` does); run the app's own code for real. In `jest.mock` factories use `jest.requireActual`, and name outer variables `mock...`.
- **Prettier** only on changed files (`format-changed.js`); do not reformat untouched files.

## Traps

- `npx expo lint` lints only `app`, `components` and `src`. Use `npm run lint` (it passes `.`).
- Expo Router lists every file under `app/` as a route: keep tests, helpers and data out of it.
- The Diet and Projections tabs render the wizard screens by importing `app/diet/*` and `app/projection/*` directly, and the same screens are also routes (opened from the profile with `?returnTo=profile`). They share one provider; do not give the route layouts their own.
- `app/(tabs)/diet.tsx` and `projections.tsx` check progress once, when the tab first opens (tabs are lazy).
- The api token lives 24 hours and the api now answers 401 for a missing, invalid or expired token (403 = wrong role). The client renews on 401 (`sessionRenewal.ts`). NetInfo is used only for `isConnected`: its reachability probe can wrongly say offline and queries would wait forever; the launch check uses `networkMode: 'always'` so offline ends on the retry screen.
- `Stack.Protected` guards run on render: navigate to `/` (always open) after changing the session store, not straight to a guarded route in the same tick.
- Web harness: select the retry button by role (`getByRole('button', { name: 'Try again' })`), the message text also contains "try again".
- `POST /users/deactivate` needs the exact text `Delete my account` (English) whatever the app language.
- The diet-preference labels do not match the stored values (ROADMAP D3); leave it. The paywall buttons are disabled on purpose (D1). The Projections tab is hidden (D2): `FEATURES.projections` in `constants/Features.ts` (default false) controls the tab (`href: null`), the intro mock scores, the FAQ question and the Pro plan lines about it; the route and code stay so the flag can bring it back. Home's sleep card opens the lifestyle questions in the profile instead.
- `react-native-keyboard-controller` is a native module. Expo Go SDK 58 ships it (1.22.7, the pinned version); an older development build must be rebuilt after the SDK upgrade. The web harness only has its no-op.
- **SDK 58 upgrade notes (WP-MOB-12).** `npx expo install expo@^5X --fix` cannot write plugins into `app.config.ts`: it stops and prints them; they are added by hand (`expo-font`, `expo-image`, `expo-localization`, `expo-secure-store`, `expo-status-bar`, defaults only). `newArchEnabled` and `edgeToEdgeEnabled` are gone (SDK 55). TypeScript 6 includes no `@types/*` by itself: `tsconfig.json` lists `types: ["jest", "node"]`. RN 0.88 strict types: no `StyleSheet.absoluteFillObject` (use `absoluteFill`), list header/footer components take `undefined` not `null`, `ImageSourcePropType` does not fit expo-image (use `AppImageSource` from `src/ui`), tab-bar icon colours are `ColorValue` (`tint()` in the tabs layout), `expo-status-bar` has no `backgroundColor`. Reanimated 4.7/Worklets 0.13 need their Jest resolver (`jest.resolver.js` chains it with jest-expo's). Shared values are written with `.set()` (React Compiler). eslint-config-expo 58 brings the React Compiler hook rules: seven older load/sync effects carry a targeted `react-hooks/set-state-in-effect` disable to refactor later, and tests may write outside a component (`react-hooks/globals` is off for `__tests__`). `expo-router` 58 wants Testing Library 14 as an optional peer; the app stays on 13 through an npm `overrides` entry (it does not use `expo-router/testing-library`). `@react-native/jest-preset` is a direct devDependency (peer of jest-expo, must match react-native). `@react-native-google-signin/google-signin` 16.2 (16.0's config plugin imported a private Expo path and broke `expo config`).
- Home shows an estimated calorie target from the onboarding answers (`services/calorieTarget.ts`, Mifflin-St Jeor); there is no api target. It says "estimated" on screen and shows nothing when an answer is missing.
- `reanimated`, `gesture-handler`, `worklets`, `expo-haptics` and `expo-image` are installed on purpose for WP-MOB-4; do not remove them as unused.
- Firebase web config and Google client ids are public identifiers in `app.config.ts`; `google-services.json` and `GoogleService-Info.plist` are tracked although `.gitignore` lists them. Never add a real secret.
- Windows: use the Write tool for files that contain backslashes or quotes; a shell heredoc can corrupt them.
- `eas.json` profiles each set `EXPO_PUBLIC_API_URL` and a channel; `app.config.ts` (`checkApiUrlForProfile`, `setCleartextTraffic`) refuses http or the `REPLACE-WITH-...` placeholder for preview and production when `EAS_BUILD_PROFILE` is set, and allows Android cleartext only for development. Channels do nothing until `expo-updates` is added (owner decision). Never run `eas build`/`submit` without the owner.
- Support e-mail addresses differ between screens (`alphafitai.com` in the FAQ, `alphafit-ai.com` in Help); that is ROADMAP D4 (owner decision), not a bug to fix here.
